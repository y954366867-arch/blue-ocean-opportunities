# 内容聚合长期规则 V5

适用所有品类；优先于V3、V4方案及旧运行提示词中关于灵感生成数量和方式的说明。搜索、候选条件、真实低粉与60天日期规则沿用现有实现。

## 核心顺序

基础内容分析 → 从真实内容发现共同创作目的 → 聚类为内容组 → 每个内容组生成一张灵感卡。

明确废止“每条视频独立生成多个灵感卡”的旧规则。不能用改写标题、拆分问价/求链接、拆分组织与互动建议等方式扩张卡片数量。标签只作分类中间信息，不能直接搬运成总结。不预设任何品类的主题名单，也不要求五个分类维度完全相同；需要可追溯的共同创作目的与逐条文字依据。

## 增量与归属

新视频先匹配已有内容组。符合共同主题则追加关联并更新同一张卡，保留组ID；不符合则发现新的内容组，资料不足则保留待聚合。每条视频只有一个主要内容组，避免重复灵感；独立评论需求必须有真实多视频评论共同支持，不能用单条评论另拆重复卡。日常包与追星痛包不能仅因同属包类合并。

每个关联保存视频ID、关联理由和逐字文字依据。卡片至少包含创作主题、共同观察、切入点、组织方式和互动建议，AI建议与文字观察分开。多条视频明确共同点及差异，点击只显示组内支持视频。仅一条视频的组标为单条参考/待聚合，不宣称共同方向。

## 失败、缓存与验收

聚类/总结失败保留参考视频及待完成状态，禁止tag/正文截取兜底。组成员或证据变化使总结缓存失效并更新；未变化复用结果。旧聚合版本卡片禁止展示。基础文字分析缓存与聚合版本分离，改聚合规则不重复分析全部内容。

必须验证：相似视频进入同组且只生成一张卡；同视频不归属多个重复组；新视频能追加到原组并保留ID；不相关内容保持分组；标签不是共同主题；旧卡失效；当前缓存重新生成无需搜索。

运行入口：bot/lib/content-analysis.ts 的共同点聚类与每组总结；bot/lib/category-v4.ts 的卡片版本过滤与待聚合处理。

### 全局去重合并审核

每轮聚类必须对所有内容组进行全局两两比较，再生成卡片。旧组仅作参考，不得逐项继承；能回答同一个具体创作问题的内容优先合并。同一商品的配色、材质、选购拆解，或同一使用需求的开箱、分享、避坑表达，不应因标题和形式不同拆成重复卡。细节和人群差异放同一卡说明。明确通勤诉求的追星人群内容可以支持通勤组；纯痛包追星内容仍独立。合并需逐条原文依据，保留已有组ID，不预设主题清单，不为减卡数强行合并缺依据的内容。

## 灵感卡表达长期规则（2026-10-12补充）

适用于所有品类和每次重新生成；本节收紧上文“卡片至少包含”的展示方式，详细分析留存，但不全部铺在主卡片上。

主卡片结构：
1. 标题：主题＋独特切入点，简短具体，避免“分享与展示”等通用词堆叠。不预设标题模板内容，不人为制造主题差异。
2. 一句话核心：这组真实内容最值得借鉴的共同点；单条组只描述该条参考，不虚称共同规律。
3. 怎么拍：最多3条具体AI创作建议，围绕本组独有的主题展开；没有分析画面时不声称原视频使用了某镜头或动作。
4. 互动切口：有评论/正文依据时说明观察；建议明确标AI建议。没有有效切口可省略，不每张都套求链接、问价格。
5. 参考视频数量及入口：点击展示全部组内视频，单条组保持单条参考标识。

详细原文观察、引用、分析依据放折叠区或详情，不恢复用户已删除的诊断大栏和冗长技术说明。观察与AI建议不能混为事实，主卡可用轻量标记区分。

表达质量：禁止直接展示tag串或正文截取作为总结；删除重复观点、模板化长段落和空泛建议。三张卡连看时应能迅速看出各自不同的创作价值；如果只有措辞不同而主题相同，应合并内容组，而不是为标题强行换词。

数量措辞必须准确：少量评论不称“大量用户”；不能把评论总数当有效讨论人数。价格不作为内容筛选条件，原文提价可作观察，但不得编造商品价格或推荐商家必须采用低价主题。

落实要求：修改实际运行的每组总结提示词和输出结构，随后使旧表达版本的总结缓存失效，用已存证据重生成；不为改文案重新大量采集。长期文档是规则来源，写入文档不等于运行提示词已更新。

验收：多个主题卡简短且差异明确，单条/多条表述准确、建议具体、无tag搬运和虚构评论数量；相关视频归属保持正确。
